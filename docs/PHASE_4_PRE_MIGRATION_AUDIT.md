## Detailed Impact Per Category

### HIGH RISK — Must update before rename

#### `.github/workflows/ci-backend.yml` (7 occurrences)
```yaml
paths:
  - 'apps-backend/api/**'       # triggers on push/PR — BREAKS if wrong
env:
  BACKEND_DIR: 'apps-backend/api'   # used as working-directory in all jobs
cache-dependency-path: 'apps-backend/api/package-lock.json'  # 4× across jobs
```
**Impact:** CI stops triggering on backend changes; all jobs fail (wrong working-directory).
**Fix:** Replace `apps-backend/api` → `apps/api` throughout (7 lines).

#### `pnpm-workspace.yaml` (1 occurrence)
```yaml
- 'apps-backend/*'
```
**Impact:** pnpm cannot discover the backend package. `pnpm install` would work but backend wouldn't be a workspace package.
**Fix:** Change `'apps-backend/*'` → `'apps/*'` (or `'apps/api'` to be explicit).

---

### MEDIUM RISK — Functional but non-critical

#### `package.json` — root db:push scripts (3 occurrences)
```json
"db:push:platform": "bash scripts/governance/prisma-safety.sh apps-backend/api/prisma/platform/v1/ ..."
"db:push:identity": "bash scripts/governance/prisma-safety.sh apps-backend/api/prisma/identity/v1/ ..."
"db:push:console":  "bash scripts/governance/prisma-safety.sh apps-backend/api/prisma/platform-console/v1/ ..."
```
**Impact:** These NPM scripts fail to find the schema directory → db:push commands break.

**Impact:** v6-migration scripts break. These are developer tooling, not production paths.
**Fix:** Update shell variable assignments and example strings.

#### `apps-backend/api/src/.../wl-db-provisioning.service.ts` (2 occurrences)
Line 128 — inside a human-readable instruction string (shown to platform admin):
